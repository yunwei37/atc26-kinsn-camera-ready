\begin{abstract}
eBPF safely extends OS kernels in domains such as networking, observability, and security. The safety comes from an in-kernel compilation pipeline: a verifier checks every program for safety, and a kernel just-in-time compiler (JIT) translates the verified bytecode to native code. The kernel keeps the JIT simple to stay trustworthy; it translates one instruction at a time. In our characterization, C code compiled through the pipeline runs up to twice as slow as natively compiled code. The clearest losses come from hardware idioms. A CPU executes an idiom directly, yet the idiom typically reaches the kernel JIT as several instructions.
%
We present \tool, a mechanism that extends the eBPF compilation pipeline via kernel modules with new operations, with minimal trusted computing base (TCB). Each operation in a \tool module carries two forms: a \emph{proof sequence} of vanilla eBPF instructions for verifier checks and a \emph{native emit} of machine instructions for JIT compilation. The native emit is the only per-operation addition to the TCB. With \tool, we build \lang, including hardware-idiom operations such as rotate and conditional select. Lean 4 proofs can further discharge that trust, showing that each native emit computes the same result as its proof sequence. On x86-64 and ARM64, \lang speeds up eBPF microbenchmarks by up to 24\% and production applications by up to 12\% over the unmodified pipeline. The same \tool mechanism supports whole-program native replacement, reaching 2.358$\times$ at the cost of a much larger TCB.
\end{abstract}
